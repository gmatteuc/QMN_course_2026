================================================================================
  Quantitative Methods in Neuroscience (QMN) - Setup Guide
  Master in Neuroscience, University of Geneva - Academic year 2026-27
================================================================================

This guide takes you from a blank laptop to a working setup for the QMN
practicals: conda + a "qmn" Python environment + the course notebooks
running in VS Code. You only need to do this once.

The TAs will walk through these steps with you in the Week 1 practical.
If you have never installed Python before, read top to bottom and run
the commands exactly as written.

The same instructions exist as an illustrated guide with screenshots,
QMN_setup_guide_students.pdf, downloaded from Moodle next to this file. It
covers the same ground: installing conda, installing VS Code, putting the
course folder together, building the environment and checking that it works.
Follow whichever of the two you prefer.


--------------------------------------------------------------------------------
  1.  INSTALL CONDA  (skip if you already have Anaconda or Miniconda)
--------------------------------------------------------------------------------

We recommend Miniconda, the minimal conda installer: it gives you conda
and a Python, and nothing else. Download the installer for your OS and
run it with the options it recommends:

    https://www.anaconda.com/docs/getting-started/miniconda/install

On Windows, leave the PATH option as the installer sets it: you will work
from the Anaconda Prompt, which finds conda on its own. Open a terminal
(on Windows the "Anaconda Prompt (miniconda3)", from the Start menu) and
verify:

    conda --version

You should see something like "conda 24.9.0". If you get "command not
found", close the terminal, reopen it, and try again.

Also install VS Code (https://code.visualstudio.com) and, from its
Extensions panel, these official Microsoft extensions:

    Python      (installs Pylance and the Python Debugger with it)
    Jupyter     (runs notebooks inside VS Code)


--------------------------------------------------------------------------------
  2.  GET THE COURSE MATERIAL
--------------------------------------------------------------------------------

If you received everything as a single zip file rather than as separate
downloads, this section is already done for you: unzip it and go to section 3.

The material is on Moodle as several separate files, so that a corrected
notebook can be replaced without you downloading everything again. You put
them together once, into a single folder, and that folder is where you work
for the rest of the semester.

  a) Download QMN_support_files.zip and unzip it somewhere convenient:

         Windows        ->  %USERPROFILE%\QMN_practicals
         macOS / Linux  ->  ~/QMN_practicals

     %USERPROFILE% and ~ both mean your own user folder, so you never have
     to type your user name. Somewhere else works too, as long as you use
     your own path below. Unzipping makes a folder called QMN_practicals
     holding data/, assets/ and src/.

  b) Download environment.yml and put it in that same folder.

  c) Download each notebook and put it in that same folder as well, beside
     data/. Do the same for every notebook posted later in the semester.

When you are done it looks like this:

    QMN_practicals/
        data/                                 from the zip
        assets/                               from the zip
        src/                                  from the zip
        environment.yml
        01_programming_fundamentals.ipynb     one Moodle item each
        02_math_refresher.ipynb
        03_probability_descriptive.ipynb
        04_inference_ttests_power.ipynb

THIS IS THE PART THAT GOES WRONG. A notebook left in your Downloads folder
cannot find the data, and its first cell fails with an error about a missing
file. The notebooks look for data/ in the folder they are sitting in, so
they have to sit next to it.

The other Moodle items do not go in the folder. This guide and its illustrated
twin are the install instructions, and the four cheat sheets, one per week, are
a page of syntax each to keep open beside you while you work. Nothing reads
them, so keep them wherever suits you.

Now open a terminal and "cd" into the folder:

    Anaconda Prompt:        cd %USERPROFILE%\QMN_practicals
    macOS / Linux:          cd ~/QMN_practicals

Run "dir" (Windows) or "ls" (macOS / Linux) and check that you see at
least:

    environment.yml
    data
    src
    01_programming_fundamentals.ipynb


--------------------------------------------------------------------------------
  3.  CREATE THE "qmn" ENVIRONMENT
--------------------------------------------------------------------------------

From the project root (the folder that contains environment.yml), run:

    conda env create -f environment.yml

IF CONDA ASKS YOU TO ACCEPT TERMS OF SERVICE, and it may, it stops and prints
a command beginning with "conda tos accept". Copy the whole line it gives you,
run it, then run the create command again. That is Anaconda asking you to
agree to their terms rather than anything being broken, and it happens once
per machine.

This installs Python and all required libraries; it takes 5-15 minutes
depending on your connection. Grab a coffee. Then activate it:

    conda activate qmn

You should now see "(qmn)" at the start of your terminal prompt. Every
Python / pip / jupyter command from this point on uses the qmn environment.

If conda says that qmn already exists, you have set it up before. Do not
remove it: update the one you have instead.

    conda env update -n qmn -f environment.yml --prune

Nothing needs to be registered: the Jupyter extension in VS Code finds conda
environments by itself, since ipykernel is part of the environment. Only if
qmn never shows up in the kernel list, or if you start JupyterLab from
outside the environment, run this once with qmn active:

    python -m ipykernel install --user --name qmn


--------------------------------------------------------------------------------
  4.  OPEN A NOTEBOOK AND CHECK YOUR SETUP
--------------------------------------------------------------------------------

In VS Code (recommended):

    code .

The fastest check, with the qmn environment active. From the QMN_practicals
folder:

    python src/check_env.py

It prints one line per package with the version you actually have, one line
per dataset, and tells you what to do if something is missing.

The same check from inside any notebook, which also verifies that the kernel
you selected is the right one:

    from src.check_env import check_environment
    check_environment()

Then open the first notebook of the course, 01_programming_fundamentals.ipynb,
and click "Select Kernel" at its top right. Choose "Python Environments" from
the panel that drops down, then pick qmn from the list.

The list names environments by their path rather than by name, and the Python
version does not tell them apart, so look for the entry whose path ends in
"envs/qmn". You will know it worked because the button at the top right stops
saying "Select Kernel" and shows the environment instead.

Then run the first two code cells (Shift+Enter): if they print package
versions and the first rows of the dataset, your setup works. The illustrated
guide has screenshots of all three moments.


--------------------------------------------------------------------------------
  5.  DAILY WORKFLOW
--------------------------------------------------------------------------------

Every time you come back to work on the course:

    cd ~/QMN_practicals      (Windows: cd %USERPROFILE%\QMN_practicals)
    conda activate qmn
    code .

You do NOT need to repeat step 3 - the environment is already there.


--------------------------------------------------------------------------------
  6.  MAINTENANCE & TROUBLESHOOTING
--------------------------------------------------------------------------------

  * To pick up a new package added during the semester:
        conda activate qmn
        conda env update -f environment.yml --prune

  * To start over from scratch (if something is broken):
        conda deactivate
        conda env remove -n qmn
        conda env create -f environment.yml

  * To list existing environments on your machine:
        conda info --envs
